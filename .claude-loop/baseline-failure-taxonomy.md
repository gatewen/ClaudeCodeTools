## 0. 一句話結論

**三閘全過清單為空。** 五個失效模式 M1–M5 中，四個（M1/M2/M3/M5）過了第一閘（fair-reproducible），但**沒有任何一個**同時過第二閘（methodology-catches：方法論真的不壞）與第三閘（cheaper-insufficient：便宜 baseline 抓不到）。M4 連第一閘都沒過。

因此，在用戶原話收斂的成功定義——「找得到一個 bug，裸寫會犯、但用方法論就不犯」——下，**目前找不到一個已成立的標的**。

## 1. 三閘全過的差異化失效模式清單

**空。**

沒有任何一個失效模式同時滿足：(a) 裸寫在真實 regime 公平地壞、(b) 方法論有具體機制真避免、(c) 便宜 baseline（裸寫+一次外部 review／裸寫+notes.md 重讀）抓不到。

這意味著：依本調查標準，**現在沒有任何標的值得直接建測試來「證明方法論的差異化優勢」**——因為連設計上能通過三閘的模式都不存在，遑論實證。

## 2. 公平任務模板

**無三閘全過模式，故無模板可給。**

唯一接近的候選（M3 介面契約漂移、M5 長時程累積漂移）卡在「方法論機制存在但在目標 regime 的有效性零實證 + 可被便宜 baseline 取代」。它們不是「值得建測試證明優勢」的標的，而是「值得做受控實驗去檢驗優勢是否存在（且很可能證偽）」的候選——這兩者性質不同，見第 5 節。

## 3. 被刷掉的模式 + 死在哪一閘

| 模式 | 過閘 | 死在 | 歸類 |
|------|------|------|------|
| M1 跨 session 不變式失憶 | 閘1✅ | 閘2❌ 閘3❌ | 方法論也會一起壞（窄子集外）+ 可被通用記憶工具取代 |
| M2 Session-2 重造輪子（DRY 消滅刻意去正規化） | 閘1✅ | 閘2❌ 閘3❌ | 方法論也會一起壞（do-NOT 無結構化欄位 + re-read 無 hook） |
| M3 跨模組介面契約漂移 | 閘1✅ | 閘2❌ 閘3❌ | 可被便宜 baseline 取代（IF-x 落盤是 artifact 紀律，非五階段 ritual） |
| M4 大 repo 只貼片段 | — | **閘1❌** | 只能靠 rig 重現差異（等裝備裸寫自己會 grep，Stage D 已實證） |
| M5 長時程累積漂移（lost-in-the-middle） | 閘1✅ | 閘2❌ 閘3❌ | 方法論也會一起壞（隱含 B 漏接）+ 可被便宜 baseline 取代 |

### 3.1 「只能靠 rig 重現」類 — M4（死在閘1）

M4 是唯一連第一閘都沒過的模式。它的失效理由（caller 檔沒貼進 context）本身公平，但「讓裸寫壞的機制」=擴大檢索半徑 grep caller，**不是方法論專屬**。Stage D 已實證：同一份 7 檔全在窗的 codebase，裸寫前沿模型「主動做了等價的影響分析」、找到全部 5 個 recompute site、漣漪 4/4 與閉環平手（stage-d/RESULTS.md 已復查）。

- 子case「兩臂都有 repo 存取」：等裝備裸寫自己 grep → 平手，零差異化。
- 子case「只貼片段、無 repo 存取」：方法論 agent 同樣 attend 不到遠端 caller → 退化回 M1，兩臂同盲同壞。

要讓 M4 出現差異，只能給兩臂不對等的 context 存取（方法論有工具、裸寫沒有）——這正是鐵律禁止的不公平 rig。**M4 = 不公平 rig，出局。**

### 3.2 「方法論也會一起壞」類 — M1 / M2 / M5（死在閘2）

這三個的共同病理：方法論宣稱「把 B 拉回窗」的機制，在目標 stale regime 下與裸寫同樣退化，無法保證「方法論不壞」這條腿。

- **M1**：機制（architect Phase 1 強制必讀「長期警惕模式」）只對「已 ≥3 次升格 + 用戶確認」的窄子集真有效。全 repo 唯二真實升格的 #006/#007 都是方法論維護類元問題；對「某 race 上季修法」這類一次性遠端不變式幾乎踩不到升格門檻。`dev:handoff load` 我核實只讀 handoff.md/今日 log/MEMORY，不 grep `.claude-loop/artifacts/` 撈 BC-x/EH-x，是通用狀態交接非不變式感知。任意遠端 B 不必被拉回窗。
- **M2**：負向不變式（do-NOT 收斂 + 理由）無結構化載體，只能靠自由 prose「設計決策」段——而 session-1 作者對自己視為理所當然的理由最不會寫。session-2 re-read 是 prose 無 hook（adversarial MEDIUM-2），壓力下被靜默略過。失效條件（理由不被記下 / 不被讀回）方法論沒有強制機制消除，只是把同一 stale 點換個位置。
- **M5**：對「architect 從未登記為 BC-x 的隱含不變式」根本沒有差異化機制——磁碟 artifact 裡沒有 B，Phase 5 正向追溯追不到不在基準裡的東西。drift 形式 (b)（跨 20 session 侵蝕）尤其落在此洞。且 verifier 步驟 5「函式 >15 個時聚焦本次修改函式」暗示它在超大尺度自我截斷——**機制在最需要它的尺度上自我退化**。

### 3.3 死在閘3（可被便宜 baseline 取代）— M1 / M2 / M3 / M5

即使放過閘2，這四個的差異化價值都收斂到**「持久化 + fresh-context／外部視角」這個通用能力**，而非五階段 ritual（11 sub-agent / BC-x / Phase 5 雙向追溯）：

- 真正把 B 拉回窗的是 **context 再注入 / artifact 落盤**——一旦 B 回窗，A–E 已證連裸寫都自發抓到，ritual 對「抓 bug」零邊際貢獻。
- M1 自承 claude-mem / AGENTS.md 達同效；M3 的 IF-x 落盤是可被便宜工作流獨立採用的 artifact 紀律；M5 的「裸寫+notes.md 自己重讀」反事實從未被排除。
- 對抗驗證報告 §4.2 已定論：「真正捕獲的是換一個外部 LLM，不是五階段儀式——歸因偷渡。」#007 全史（cross-source 2/2 vs 自審 0/2）顯示承重因子是「換 fresh/外部視角」，不是儀式。

## 4. 三閘全過清單為空的意涵

這是本報告最重要的結論，必須直球講。

**對方法論意味著什麼：**

1. **核心商業承諾（差異化代碼/設計品質）目前無立足點。** A–E 五場全天花板平手、零 correctness 增益、成本 +40%→+590%，已直接證明「在前沿模型單 context 能認真處理的任務」上，模型本身已把這些做對，閉環只疊成本。M1–M5 的三閘分析進一步證明：連「理論上能通過三閘」的失效模式都構造不出來——每個候選不是不公平（M4），就是方法論一起壞（M1/M2/M5），就是價值落在可被便宜取代的「持久化/外部視角」（全部）。

2. **方法論真正承重的價值，從來不是五階段 ritual，而是「外部化持久 + 換一個視角」這兩個通用動作。** 這兩個動作 claude-mem / AGENTS.md / handoff note / 一次 Codex review 都能提供，不需 11 sub-agent ceremony。方法論把通用動作包進昂貴儀式，並把儀式的功勞算到自己頭上——這是 §4.2 點名的歸因偷渡，三閘分析每一條 caveat 都重複撞到它。

3. **二階風險真實存在。** adversarial HIGH-4：最重的閉合保證在配額耗盡的長 session 後段自動降級為 single-source 自審——而長 session 正是 M1/M5 最該發作的場景。**方法論在最需要硬的時刻反而最軟。** verifier >15 函式自我截斷（M5）是同一病理的另一面。

4. **這不是「已證偽」，是「無已驗證優勢 + 結構性懷疑」。** M3/M5 指向 A–E 五場一致標記的唯一未否證 regime（超大型/長時程多 session），那裡確實未被任何 oracle 摸過。誠實的狀態是：**未證有用 ≠ 證明有用。** 把「未否證」當「已驗證價值」是 confirmation bias，方法論自己的 learning-log:7 也警告過這點。

## 5. 對用戶原想法的直接回答

> 「找出裸寫會犯、而方法論不犯的 bug」——這件事可行嗎？

**可行的部分（窄、且尚待實證）：**

理論上唯一還活著的縫，是 A–E 摸不到的 regime——**B 不在窗、且 B 曾被顯式契約化並持久落盤、後續 session 重載**。具體兩個候選值得做受控實驗（不是「建測試證優勢」，是「檢驗優勢是否存在」）：

- **M3 介面契約漂移**：唯一機制骨架已在（IF-x on-disk 是裸寫結構上沒有的離線真相）、缺口是工程性（消費端 read-interfaces 無 hook 強制 + CR-x 自動傳播是未實作 v3）。實驗必須拆三臂以隔離歸因：**裸寫無 IF-x 慣例 / 裸寫+IF-x 落盤慣例 / 完整閉環**——若中臂就拿走大部分增益，證明承重的是 artifact 不是 ritual。
- **M5 長時程累積漂移**：須跑真實跨 session 長時程，且至少三臂含「**裸寫+notes.md fresh-window 重讀**」第四臂以隔離「外部化記憶」這個通用動作。預登記預測應同時包含「兩臂皆壞」的可能（do-NOT/隱含 B 既沒人記、prose 閘又被略過）。

oracle 中立性要求：bug 由獨立凍結種子定義、不給測試檔、不給 bug 數提示（沿用 A–E 協議）；嚴禁為了讓裸寫失敗而藏雷/混淆耦合（Stage D 已證「公平=可發現=平手」）。

**死路的部分（明確）：**

- **靠 rig 讓裸寫失敗 = 死路。** Stage D 鐵證：藏到能騙過前沿模型仔細 review 的耦合，依定義就是不公平混淆，判出局。M4 整個是這條死路。
- **指望五階段 ritual 本身（BC-x/Phase5/11 sub-agent）產生差異 = 死路。** 每個候選的承重因子都坍縮到「持久化 + 外部視角」，這是通用能力，便宜 baseline 全提供。ritual 不可替代性在 M1–M5 全部舉證失敗。
- **隱含不變式（Hyrum's Law / 業務語意錯誤）= 死路。** architect 枚舉 BC-x 同受 window 限制，契約之所以隱含正因當下沒人覺得是契約——方法論與裸寫同壞（M2/M5 + adversarial HIGH-1 GIGO）。
- **單 context、≤900 行、單 session 的任何任務 = 死路。** A–E 已五場否證，換語言/換任務型態大概率同結論（Stage A 建議已明示）。

**最誠實的總結：**

「找出裸寫會犯而方法論不犯的 bug」——**可行性窄到只剩「跨 session + 顯式契約化 + 持久重載」一條縫，且該縫的增益大概率歸功於『外部化持久 + 換視角』這兩個通用動作，而非五階段儀式。** 即使 M3/M5 實驗跑出差異，最可能的結論是「方法論的有用部分等價於一個 handoff note + 一次外部 review」，而不是「五階段閉環不可取代」。若實驗跑出「兩臂皆壞」或「便宜中臂≈完整閉環」，則正式證偽方法論的公平差異化優勢——而依目前所有證據方向，這比證實更可能。
