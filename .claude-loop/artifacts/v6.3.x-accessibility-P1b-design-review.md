## 審查結果

### DR-1 [high]：行數預算緩衝違反 #006 硬規則 + 結構化區塊低估風險

**問題**：
1. **根 README.md**：Section 6 表格列「上限 ≤ 215 行 / 緩衝 0」，明確被 #006 預防做法 (c) 「緩衝 ≥ 5 行硬規則」否決。設計者在 RISK-1 自己標 ❌ 並提議「上限改 220」但**沒在 Section 6 表格更新**——表格仍寫 215。實作時會以表格為依歸 → 直接踩雷。
2. **「11 行微小直通保護段」是 #006 預防做法 (a) 定義的「結構化區塊」**（含醒目排版 / 列表 / 強調語句），按 (a) 應估 ≥ 15-20 行。設計者只估 11 → 真實增量可能 +22 ~ +27 行 → 即使上限拉到 220 仍可能 < 5 緩衝。
3. **方法論運作指標.md**：Section 6 表格列「上限 ≤ 116 行 / 緩衝 4 ⚠️」直接違反 #006 (c)。括號內建議「附錄壓 ≤ 20 行 → 緩衝 9」沒有作為硬上限寫入 BC-1 驗收。BC-1 自己只說「≤ 25 行」，跟表格的 25 行增量一致，但跟「壓 ≤ 20 行」的緩解措施衝突 → 實作者不知道遵循哪個。

**影響**：
- v6.0.0 #2 / v6.0.0 #3 / v6.2.0 R-1 三次連續預算爆掉，#006 才升格為長期警惕模式。本次 DR 又踩一樣的洞 → 升格規則失效。
- 實作期一旦超出，需 reflow 內容或拉高上限，引入 P3 額外修補成本。

**建議修正**（P1 立即修，無需重做）：
1. **根 README**：Section 6 表格上限改 **≤ 220 行（緩衝 5）**，且 BC-2 行數限制段同步改 220。微小直通保護段預算從 11 → **20**（按 #006 (a) 結構化區塊下限），總增量 +27 行（5 定位 + 2 連結 + 20 保護段）→ 上限改 **≤ 225 行（緩衝 5）** 比 220 更穩。
2. **方法論運作指標.md**：BC-1 行數限制改 **≤ 20 行附錄**（不是 25），表格上限改 **≤ 111 行（緩衝 5）**，緩解措施提到的「壓 ≤ 20 行」直接寫進 BC-1 驗收條件 BC-K-A1 第三條（從 ≤ 116 改 ≤ 111）。
3. **驗收條件**：建議 BC-K-A1 / BC-K-A2 加一條「P3 完成後 reviewer 主動 wc -l，緩衝實測 ≥ 5」（沿 #006 預防做法 b）。

### DR-2 [medium]：QUICKSTART.md vs dev-closed-loop/README.md 內容分工需在 BC-3 落地

**問題**：RISK-4 用一句話描述分工（「30 分鐘上手 use-case 視角 vs 文件結構索引 reference 視角」），但 BC-3 內容大綱不見「不重複既有 README 哪些內容」的明確排除清單。dev-closed-loop/README.md 149 行已有「快速開始」「文件導覽」「五階段方法論摘要」等段落。QUICKSTART 的 5 核心概念（閉環五階段 / BC-x EH-x / 三段任務分流 / 認知驗證 / 學習自動沉澱）有 ≥ 2 個跟既有 README 高度重疊 → 實作者容易寫成「另一份結構索引」。

**影響**：兩份檔案都讀的人會覺得冗餘 → 採納門檻反而沒降低。BC-K-A3 驗收只 grep heading 命中，無法擋這個失敗。

**建議修正**：
- BC-3 內容大綱加一條「**排除原則**」：QUICKSTART 不重複 dev-closed-loop/README 的「文件導覽」「目錄樹」「Skill 安裝步驟」；只走「我有個 task → 該怎麼用閉環」的決策樹路徑。
- BC-K-A3 加一條驗收：「QUICKSTART.md 跟 dev-closed-loop/README.md diff 同段落字串相似度 < 30%」（人工檢查或 P3 quality 階段比對）。

### DR-3 [medium]：英文版翻譯品質的 Falsification 雖標不適用，但「微小直通保護」術語英譯需 BC-2 顯式約束

**問題**：步驟 5c Falsification Check 標「不適用」正確（純文檔無外部事實），但 README.en.md 涉及一個翻譯陷阱：「微小直通保護」「中型精簡六步」「大型完整 5-Phase」這三個三段任務分流的核心術語，目前 v6.3.0 中文 README 已經是修煉完的對外用語（K-x 隱去）。BC-2 沒指定英文版用什麼字串對應 → 譯出來可能是 literal translation（"tiny direct-pass protection" 等），讀起來像機器翻譯而非 idiomatic English。

**影響**：採納門檻分數（5.5→7）的提升取決於英文版是否「能 grasp」。術語不流暢 → 國際讀者第一印象差 → 預期 +4.2 達不到。

**建議修正**：BC-2 加一條：英文版三段任務分流術語建議用 `tiny / direct merge`、`small-to-mid / 6-step lite loop`、`large / full 5-phase loop`（或設計者擇選類似 idiomatic 對應）。實作時在 README.en.md 引入 glossary 段。
