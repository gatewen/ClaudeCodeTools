### DR-2 [arch-risk] — K-11 KPI 機制無強制量測義務，存在「裝飾性文檔」長期風險

**問題**：

### DR-4 [medium] — 第 5 條 5.4 解除條件「同 1-4 條」邏輯不對稱

**問題**：

P1 line 78-79 第 5 條 5.4 解除條件：

> 用戶補充證據 / 確認「中度推論可接受」/ 說「OK 用原方案」→ 立即解除執行（同 1-4 條）

「同 1-4 條」這個聲明值得質疑：

- 1-4 條 push back 是 Claude 反對**用戶提出的方案**（替代方案 / anti-pattern / 弱證據 / 任務過大）— 用戶說「OK 用原方案」表示「我承擔風險，執行原方案」，符合 Q1 Think 尊重最終判斷
- 5 條反向質疑是 Claude 質疑**用戶斷言的事實前提**——若用戶說「OK 用原前提」而不補證據，Claude 是基於可能錯誤的事實前提去執行後續行動，**錯的不是方案而是事實本身**

兩種「OK」的代價結構不同：1-4 條的代價在「方案次優」（已知可量），5 條的代價在「事實錯誤導致 rollback / 路徑錯誤 / memory 污染」（未知不可量，正是 5.1 第 4 條觸發條件）。把「OK 用原前提」直接等同於「OK 用原方案」，會讓 5 條的設計目的（捕捉事實誤判）失效——用戶一句「OK」就繞過。

**影響**：

K-14 第 5 條設計初衷是補 v5.22.3 「事實誤判」事件這一類問題（用戶斷言 X 實際 Y → Claude 不查證直接執行 → 後果嚴重）。若 5.4 解除條件過寬，等於設計了質疑機制但又留了一個「用戶說『OK』就跳過」的後門，5.1 觸發場景的把關價值大幅折損。

**建議修正**：

5.4 解除條件改為**分支處理**：

- 「用戶補充 A 級證據」→ 立即解除（事實已驗證）
- 「用戶確認 B 級 + 反例通過」→ 立即解除（事實有合理依據）
- 「用戶說『中度推論可接受』」→ 解除執行，但 Claude 須在 inline 對話標注「⚠️ 基於未驗證前提執行，事實若錯誤代價：[列舉]」（讓用戶看到代價的對等性同 1-4 條 push back 精神）
- 「用戶說『OK 用原方案』但不補證據、不確認推論等級」→ **不自動解除**；要求用戶 explicit 說「中度推論可接受，我承擔事實錯誤代價」

這樣既尊重用戶最終判斷（Q1 Think），又避免「一句 OK 繞過質疑」的後門，跟 1-4 條的 push back 解除保持「精神同調但機制差異」的合理對稱。

### DR-5 [medium] — BC-4 驗收標準「7 處 ≥ 1 命中」對條件式項目有歧義

**問題**：

P1 BC-4「位置」列 7 處同步點，其中第 6 / 7 點是條件式：

- 第 6 點：「`setup.sh` 驗證清單若有 hardcode `.claudedocs/concepts/` 檔案數需更新（步驟 2 前 grep 確認）」
- 第 7 點：「`dev-closed-loop/skill/init-claude.md` 部署清單若有 hardcode 需更新」

但「驗收」聲明：「grep `v6.2.0` 在 7 處檔案各 ≥ 1 命中」——若 setup.sh / init-claude.md 沒有 hardcode（不需要更新），它們不會出現 v6.2.0 字串，驗收會失敗。設計者意圖是「條件不觸發 → 該檔案不算入 7 處」，但驗收文字未表達。

**影響**：

迷你追溯（步驟 4.5）反向追溯時可能出現假失敗或需要人工判讀「為什麼這個檔案沒命中是 OK 的」。也可能誤導實作者（程序設計師看到驗收要求「7 處 ≥ 1 命中」會強加 v6.2.0 註解到 setup.sh，產生噪音改動）。

**建議修正**：

驗收標準改為兩段式：

```
驗收：
- 必同步（5 處）：CLAUDE_TEMPLATE.md 末尾 / migration-notes / dev-closed-loop/README.md / 根 README.md / .claudedocs/README.md — grep `v6.2.0` 各 ≥ 1 命中
- 條件式（2 處）：setup.sh / init-claude.md — 步驟 2 前先 grep `.claudedocs/concepts/` hardcode 數，命中 → 同步更新並驗 v6.2.0 ≥ 1；未命中 → 標 N/A
```

### DR-6 [medium] — K-10 對應表「常見/邊界」二元化資訊增益薄

**問題**：

P1 BC-2 對應表 7 列 × 4 欄，「常見 failure_type」欄高度重複：

**影響**：

不影響正確性，但 v7 重評時可能發現 K-10 表很少被查（因為實際歸類時直接看「教訓欄附判定理由」即可，不靠表）。

**建議修正**（由用戶決定）：

- **方案 A**（保留現狀）：用戶已核可，照做；實作時 K-10 表行數可壓 ≤ 18 行（standards 緩衝多 7 行，間接幫 DR-1 留空間給其他檔案）

- **方案 C**（補強現狀）：保留 7×4 表但加一段「常見高度重複是因為 ID 系統 vs failure_type 是多對少對應」的設計理由說明，避免讀者把表當「精準對映」誤用
