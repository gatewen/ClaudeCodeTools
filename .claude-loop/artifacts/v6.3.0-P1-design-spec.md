## 2 邊界條件（BC-x）

### BC-1 [testable]：5 個 anti-pattern 對照範例檔案（K-07 主體）

**位置**：`.claudedocs/examples/0X-{slug}.md`（5 個檔案）

**檔案清單與每檔 5 段結構大綱**：

```
01-think-before-coding.md（Q1 Think · 80-120 行）
├─ ## 場景：用戶說「修一下這個 API 讓它快一點」
├─ ## 錯誤示範：默默選一種解讀（例：把 GET 改 POST 加 cache）
├─ ## 原則診斷：Q1 Think 違反 — 沒列假設、沒問澄清；對映 CLAUDE_TEMPLATE Section 0 Q1
├─ ## 修正版本：列出 3-4 個假設 + AskUserQuestion 確認 → 動手
└─ ## 關鍵限制：純技術問題不需 push back（5 條白名單）；含糊需求才適用

02-simplicity-first.md（Q2 Simplicity · 80-120 行）
├─ ## 場景：用戶要計算「打折後價格 = 原價 × 折扣率」
├─ ## 錯誤示範：用 Strategy pattern + Factory 處理單一計算
├─ ## 原則診斷：Q2 Simplicity 違反 — 過度設計；對映 CLAUDE_TEMPLATE 步驟 1 自檢 ⑦ senior engineer test
├─ ## 修正版本：一個函式直接算（calculatePrice(original, discount)）
└─ ## 關鍵限制：未來變化已知時用合理抽象；單純計算不要 builder/factory

03-surgical-changes.md（Q3 Surgical · 80-120 行）
├─ ## 場景：用戶報「README 裡有個 typo `recieve` 應為 `receive`」
├─ ## 錯誤示範：修 typo 順手 reformat 引號 + 加 type hints + 重命名變數
├─ ## 原則診斷：Q3 Surgical 違反 — 改太多；對映 Section 11.5 Dead code 立場 + Section 11 同類掃描
├─ ## 修正版本：只改 typo 那行；附註「我注意到 X / Y 也可改但未動」
└─ ## 關鍵限制：用戶 explicit 要求 cleanup 才動別的；同類掃描例外

04-goal-driven-execution.md（Q4 Goal · 80-120 行）
├─ ## 場景：用戶報「測試 test_user_login 失敗」
├─ ## 錯誤示範：「我先 review 整個 auth.py 再改善」
├─ ## 原則診斷：Q4 Goal 違反 — 沒先定可驗證目標；對映 architect Step 1.5 命令式→可驗證目標 + Section 0 Q4
├─ ## 修正版本：寫 minimal repro → 讓 test pass → 確認無回歸（具體驗證序列）
└─ ## 關鍵限制：需求模糊時 Q1 Think 釐清；目標明確才 jump 到 Goal

05-cross-artifact-mismatch.md（閉環特色 · 80-120 行）
├─ ## 場景：架構師設計「處理 5 種錯誤」、程序設計師實作 3 種、測試師測 2 種
├─ ## 錯誤示範：傳統 Code Review 看不到（每階段獨立檢查產品正確性，無跨階段對齊）
├─ ## 原則診斷：閉環特色 — Q4 Goal 的延伸（不只 setup goal，還要驗證 cross-artifact alignment）；對映 Phase 5 雙向追溯 + BC-x/EH-x ID 系統
├─ ## 修正版本：BC-x 編號 → Phase 1 5 條 BC → Phase 2 5 個實作分支 → Phase 4 5 個測試 → Phase 5 verifier 雙向比對 5/5
└─ ## 關鍵限制：精簡閉環只做正向覆蓋（迷你追溯），中型任務反向追溯 ROI 不值得；大型才走完整 Phase 5
```

**每檔包含具體程式碼範例**：錯誤示範 + 修正版本各 1-2 個程式碼塊（合計 ~30 行 code 占行數預算）。

**行數限制**（沿用 #006 預防做法 a — 每檔單獨估，DR-5 low 採納明示比例）：
- 每檔 80-120 行（含 heading + 5 段 + 程式碼範例 + 結尾連結）
- 內部比例：prose ~50-70 行（場景/診斷/限制 文字描述）+ code ~20-40 行（錯誤示範 + 修正版本各 1-2 個程式碼塊 + 必要 inline）+ heading/結構 ~10 行
- 5 檔合計：400-600 行（新檔，無預算上限）
- 緩衝：每檔 buffer 40 行（預期 80 行寫法可彈性到 120）

**驗收**（6 子條目 BC-K07-x 全部命中）：
- BC-K07-1：5 個檔案存在於 `.claudedocs/examples/01~05-*.md`
- BC-K07-2：每檔含 `## 場景` `## 錯誤示範` `## 原則診斷` `## 修正版本` `## 關鍵限制` 5 個 heading
- BC-K07-3：每檔行數 80-120 行（wc -l 範圍檢查）
- BC-K07-4：grep `Q1 Think` 在 01.md / `Q2 Simplicity` 在 02.md / `Q3 Surgical` 在 03.md / `Q4 Goal` 在 04.md / `跨產出物矛盾` 在 05.md 各 ≥ 1

- BC-K07-6：跨檔同步 — 4 處 v6.3.0 字串各 ≥ 1（CLAUDE_TEMPLATE / dev-closed-loop/README / 根 README / .claudedocs/README）+ setup.sh 條件式（17/17 字串 ≥ 1 + 5 個 examples/ 條目 ≥ 1）
