## 2. 6 樣本實證分析

### 2.1 DR-x high 分布

| 樣本 | DR-x high 數 | 對應 |
|------|-----|------|
| v6.0.0 | 1 | DR-1 IF-1 placeholder migration anchor |
| v6.1.0 | 0 | — |
| v6.2.0 | 1 | DR-1 concepts/閉環核心理念.md 緩衝為 0 |
| v6.3.0 | 0 | — |
| dogfooding T1 | — | 直通 |
| dogfooding T2 | 0 | DR-1 medium 當場修（不計 high）|

**統計**：5 個有效樣本中 2 樣本 DR-x high = 1（40%），3 樣本 = 0（60%）。當前門檻「≤ 1 🟢 / 2-3 🟡 / ≥ 4 🔴」。

**初步校準判定**：
- 樣本中無 ≥ 2 觀察 → 警示 / 危險區門檻**未經實測驗證**
- 健康區（≤ 1）有 100% 樣本符合 → 門檻偏鬆？或 v6.x 系列普遍小規模？需更多樣本

### 2.2 R-x high 分布

| 樣本 | R-x high 數 | 對應 |
|------|-----|------|
| v6.0.0~v6.1.0 | 0 | — |
| v6.2.0 | 1 | R-1 行數預算超出 18 行（升格 #006） |
| v6.3.0 | 0 | — |
| dogfooding T2 | 0 | 3 medium 用戶延後（不計 high）|

**統計**：5 個有效樣本中 1 樣本 R-x high = 1，4 樣本 = 0。當前門檻「= 0 🟢 / = 1 🟡 / ≥ 2 🔴」。

**初步校準判定**：v6.2.0 R-1 觸發升格 #006，預防做法在 v6.3.0 / dogfooding 都驗證有效（無重複觸發）→ 門檻**驗證合理**。

### 2.3 升格頻率（per 月）

當前累積 1 個升格（#006）/ 1 個月 = 1/月，落在「健康 1-3 / 月」區間。

**校準判定**：時間跨度太短（1 個月）→ 此維度**無法校準**，等 ≥ 3 個月。

## 3. v7 校準建議草案

| 維度 | 當前門檻 | 6 樣本實證 | 建議方向 |
|------|---------|-----------|---------|
| DR-x high | ≤ 1 / 2-3 / ≥ 4 | 樣本內 max = 1 | **保留現狀 + 累積 ≥ 10 樣本後再判**（資料不足以調）|
| R-x high | = 0 / = 1 / ≥ 2 | 樣本內 max = 1 + 升格成功 | **保留現狀**（已實證有效）|
| 升格頻率 | 1-3 / 月 | 1 個月 1 升格 | **等 3 個月後校準** |

**結論**：v7 KPI 校準**不立即修改門檻**，但本 design 文件是 v7 規劃的數據起點。下一輪 dogfooding（補 T3 + 跨 session + 跨 repo 場景）將提供更豐富樣本。

## 4. dogfooding §8 缺口清單（v7 必補）

整理 reviewer §8 的 5 個缺口，作為 v7 規劃必補項：

| 缺口 | 為何重要 | 預估補法 |
|------|---------|---------|
| **T3 大型完整 5-Phase 實戰** | 大型路徑樣本仍只 v6.0.0 一筆；P5 整合自證 / 雙向追溯 / verifier 委派全無實戰 | 新 session + 工具齊全環境跑 T3 簡化版（單 module scanner 起步），再擴 3 模組 |
| 多模組 IF-x 契約 | 跨模組依賴契約管理在實戰中是否有效未知 | 含在 T3 |
| 跨 session 持久化測試 | `.claude-loop/` 跨 session 復原機制未驗證 | 0.5 session：跑 T2 中斷後新 session 恢復 |
| 跨模組 CR-x 變更管理 | API 變更追蹤機制未驗證 | 0.5 session：跑 IF-x 變更場景 |
| bats / shellcheck 安裝後實戰 | 工具齊全環境的實戰 baseline 缺失 | 含在下次 dogfooding 中（pre-flight 補裝 bats + shellcheck）|

## 5. v7 啟動條件

達成下列**全部**條件方啟動 v7 milestone（不是 dogfooding-2，是 v6.x → v7 大版本）：

1. ✅ K-11 baseline ≥ 5 個閉環（已達 6）
2. ❌ 時間跨度 ≥ 3 個月（當前 1 個月）
3. ❌ T3 大型 5-Phase 實戰樣本 ≥ 1（dogfooding-1 deferred）
4. ❌ 跨 session / 跨模組 / 跨 repo 樣本各 ≥ 1
5. ❌ §8 5 個缺口中 ≥ 3 個已補上

**估算最早啟動時機**：2026-07-26（3 個月後）+ 中間補 1-2 次 dogfooding。

## 6. v7 預期變化（推測）

基於 dogfooding §5 + §6 + §8，v7 大版本**可能**含：

- **規則層**：Section 1.5 探索邊界進化（+ 探索類動作的 token 觀測機制）
- **流程層**：配額管理從 ad hoc 變預測式（自動 token estimator）
- **Agent 層**：design-reviewer 步驟 4.5 進化（自動偵測 BC ↔ 健康路徑階層漂移）
- **觀察層**：K-11 三指標可能加第 4 個（cost / 效率 metric）
- **適應層**：補語言指南 + 領域偵測（dogfooding §1.2 暴露的工具缺失問題）

不保證一定做，視 v7 啟動時的累積數據而定。
