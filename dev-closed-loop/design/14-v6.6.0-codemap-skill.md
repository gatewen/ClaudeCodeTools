├─ manifest-time: <ISO8601>
├─ last-code-change: <ISO8601>
├─ commits-since: <N>
├─ thresholds: days=<N> / commits=<N>

```

### IF-8：Confidence Transition Rules（Round 4 修訂 · DR-XR-4 + DR-XR-5）

> 寫入 `references/confidence-tiers.md`。**所有 transition 由方法論 agent / sync worker 觸發**，使用者不應手動編輯 confidence 欄位。
>
> **Round 4 修法**：
> - `auto-synced-verified` 改名 `phase5-referenced`（窄義：Phase 5 只看過此 entry 與設計-實作-測試一致，**不**意味依賴圖完整或 LLM 描述準確）
> - **新增** `deterministic-confirmed` tier（tree-sitter backend 確認 symbol identity + signature 一致；最強信任）
> - verifier **不直接** 修改 manifest（DR-XR-4），改成 emit 候選到 `.claude-loop/artifacts/P5-codemap-candidates.md`，下次 sync 經 deterministic check 才應用

**Tier 階梯**（信任度從低到高 · Round 5 修 · DR-R4-4 補完）：

```
quarantined              ← 候選 deterministic check 失敗 / hash 嚴重不一致（不被 agent 信任）
  ↓ (人工 review 後)
auto-synced              ← init / sync 新寫入預設 (純 LLM 產出)
  ↓
phase5-referenced        ← Phase 5 verifier 看過且與設計一致 (sync 應用候選後)
  ↓
deterministic-confirmed  ← tree-sitter backend 確認 (symbol identity + signature 機械驗證)
  ↓
human-validated          ← 人類人工 sign-off (有 hook 警告非建議)

任一狀態 + hash 不對 → STALE (runtime, 非持久化)

中介 transient 狀態（不寫進 manifest，存於 `.claude-loop/artifacts/P5-codemap-candidates.md`）:
- pending-review          ← verifier 已 emit 候選，等 sync 下次跑做 deterministic check
```

**Transition 矩陣**（Round 5 完整）：

| From | To | Trigger | Actor | 修改方 |
|---|---|---|---|---|
| (new) | auto-synced | init / sync 新寫入 | worker / sync skill | sync skill |
| (none in manifest) | pending-review | Phase 5 verifier 認為 entry 與設計/實作/測試一致 → emit 候選 | verifier (寫候選檔，**不**動 manifest) | verifier 寫 `.claude-loop/artifacts/P5-codemap-candidates.md` |
| pending-review | phase5-referenced | 下次 sync 跑 deterministic check (hash + path + symbol-id 一致) → 應用候選 | sync skill | sync skill (修改 manifest) |
| pending-review | quarantined | 下次 sync 跑 deterministic check **失敗** (hash 不對 / path 不存在 / symbol-id 不存在) | sync skill | sync skill (manifest 加 `quarantined` 標記 + drift report) |
| auto-synced | deterministic-confirmed | tree-sitter backend 確認 symbol identity + signature | sync worker (tree-sitter mode) | sync skill |
| phase5-referenced | deterministic-confirmed | tree-sitter 後確認 (升級) | sync worker | sync skill |
| quarantined | auto-synced | 人工 review 後決定信任 | user | user (有 hook 警告) |
| any | STALE | hash 不對 | 任何方法論 agent (runtime) | runtime, 非持久化 |
| deterministic-confirmed | auto-synced | hash 不對且 backend 標記 lines fallback | sync worker | sync skill |
| any | human-validated | 使用者人工編輯 manifest | user (hook 警告) | user |
| human-validated | auto-synced | hash 不對 | sync worker + 警告 | sync skill |

**語意約束**：
- STALE 不持久化寫進 manifest — 運行時 agent 偵測到就 fallback
- `pending-review` 為 transient 狀態，存於候選檔不存於 manifest
- `quarantined` 寫進 manifest（讓 agent 知道「這條曾被 verifier 提名但機械驗證失敗，別信」）
- human-validated 不被自動 demote（除非 hash 變）
- 所有 transition 必須更新 `last-validated` 時間戳
- **verifier 永不直接修改 manifest**（DR-XR-4）— 只產候選清單，sync 經 deterministic check 才應用
- `phase5-referenced` ≠ `correct`，只代表「Phase 5 在那次閉環觀察到 entry 與設計-實作-測試鏈一致，且 sync 後續做 deterministic check 通過」（Round 5 補強 DR-XR-5 / DR-R4-4）
- `deterministic-confirmed` ≠ `correct in semantic`，只代表「tree-sitter 確認結構正確」 — LLM 寫的 Functional/Constraints 仍可能不準確（保留給 human-validated）

### IF-9：Marker Recognition Contract

> 寫入 `references/codemap-integration.md`。**所有方法論 agent（architect / design-reviewer / code-reviewer / verifier）讀到 IF-x 條目時必須識別這些 marker**。

**Marker 列表**（Round 5 修 · DR-R4-2 與 IF-2 對齊）：

| Marker | 必要性 | 範例 | 用途 |
|---|---|---|---|
| `<!-- symbol-id: <lang>::<path>::<qualified-symbol>::<sig-hash> -->` | 必要 | `<!-- symbol-id: typescript::src/auth/user.ts::getUserById::sha256:abc... -->` | 主鍵（取代舊 code-hash） |
| `<!-- source: <path>:<start>-<end> -->` | 必要 | `<!-- source: src/auth/user.ts:42-67 -->` | 定位原代碼 |
| `<!-- raw-hash: sha256:<hex64> -->` | 必要 | `<!-- raw-hash: sha256:a3b9c2... -->` | line-range 原始 hash |
| `<!-- normalized-hash: sha256:<hex64> -->` | 必要 | `<!-- normalized-hash: sha256:d4e8f1... -->` | 去 comment/whitespace 後 hash（抵 false positive） |
| `<!-- index-version: <ISO8601> -->` | 必要 | `<!-- index-version: 2026-05-29T14:23Z -->` | 索引版本時間戳 |
| `<!-- confidence: <tier> -->` | 必要 | `<!-- confidence: auto-synced -->` | 信心等級（含 quarantined） |
| `<!-- backend: tree-sitter \| lines -->` | 必要 | `<!-- backend: tree-sitter -->` | 標 entry 由哪 backend 產 |
| `<!-- last-validated: <ISO8601> \| - -->` | 必要 | `<!-- last-validated: - -->` | 最後驗證時間 |
| `<!-- candidate-source: P5-codemap-candidates.md#<line> -->` | 可選 | — | 從 verifier 候選升格時記錄來源 |
| `<!-- deprecated-since: <ISO8601> -->` | 可選 | — | 標 deprecated 用 |
| `<!-- supersedes: IF-{X} -->` | 可選 | — | rename 確認後標 |

**識別契約**：agent 讀 IF-x 條目時：
1. 若**必要 marker 缺任一**（10 個必要 marker 見上表）→ entry 視為損毀（EH-5）
2. 若 confidence = `auto-synced` → 強制 cross-check 原代碼（BC-10）
3. 若 hash 比對失敗（raw-hash AND normalized-hash 都不對）→ fallback 讀原代碼（BC-9 + STALE 處理）
4. 若 raw-hash 不對但 normalized-hash 一致 → 視為「comment/whitespace 變動」，仍信任語義
5. 若 confidence = `phase5-referenced` 且 hash 比對成功 → 中度信任（仍建議 cross-check 對外契約變動）
6. 若 confidence = `deterministic-confirmed` 且 hash 比對成功 → 信任 entry 結構（但 Functional/Constraints 描述仍可能不準確）
7. 若 confidence = `human-validated` → 信任 entry 內容（但若 hash 不對則打 hook 警告）
8. 若 confidence = `quarantined` → **不信任** entry，強制 fallback 讀原代碼（Round 5 補 · DR-R4-4）

### IF-10：Tree-sitter Backend Contract（Round 4 新 · DR-XR-1）

> 寫入 `references/backend-tree-sitter.md`。**可選 dependency** — 偵測不到時 sync skill 自動降級 lines backend。

**偵測機制**（Round 5 修 · DR-R4-3 補強 — 真實 parser 可用驗證，不只 CLI 存在）：

```bash
# Step 1: 偵測 tree-sitter CLI
which tree-sitter || (test -x node_modules/.bin/tree-sitter && PATH="node_modules/.bin:$PATH")

# Step 2: 對偵測到的語言驗證 grammar 可用（非只「裝了 CLI」）
for lang in $(detect_project_languages); do
  case $lang in
    typescript|javascript)
      tree-sitter generate --check tree-sitter-typescript >/dev/null 2>&1 || mark_unavailable $lang
      ;;
    python)
      tree-sitter generate --check tree-sitter-python >/dev/null 2>&1 || mark_unavailable $lang
      ;;
    # ... per language
  esac
done

# Step 3: 對可用 grammar 跑 smoke parse（確認真能解析範例代碼）
echo 'function foo() { return 1; }' | tree-sitter parse --quiet --silent tree-sitter-typescript || mark_unavailable typescript

# 全部失敗 → backend = lines fallback
# 部分失敗 → 該語言降 lines, 其他維持 tree-sitter (mixed mode)
```

**Tree-sitter mode 行為**：
- worker 收到 `backend: tree-sitter` + `language: <lang>` 時：
  1. 用 `tree-sitter-<lang>` parser 抽 AST → 取 method/function nodes 的 byte range
  2. 用 AST query 抓 callgraph edges（具體 query 範例見下）
  3. 輸出帶 `backend: tree-sitter` marker 在 IF-x entry
  4. Forward edges 標 `confidence: confirmed`
- 後續 sync 的 hash 比對 + signature 驗證可升 `deterministic-confirmed`

**AST query 範例**（TypeScript）：

```scheme
; query: 找所有 function 宣告 + method 宣告
(function_declaration
  name: (identifier) @function.name
  parameters: (formal_parameters) @function.params
  return_type: (type_annotation)? @function.return-type) @function.def

(method_definition
  name: (property_identifier) @method.name
  parameters: (formal_parameters) @method.params) @method.def

; query: 找 call expressions
(call_expression
  function: [(identifier) (member_expression)] @call.callee
  arguments: (arguments) @call.args) @call.expr
```

**驗證方法**（Phase 2 spike 必過）：
- 至少 TS/JS + Python 兩語言提供 fixtures（含 class method / arrow function / decorator / decorator chain / generator / async function）
- 對每個 fixture 跑 worker，驗證：
  - 抽出的 symbol count ≥ ground truth × 95%
  - 抽出的 signature 與 ground truth 一致
  - 抽出的 callgraph edges 與 ground truth 對比 precision ≥ 90% / recall ≥ 80%
- 失敗 → tree-sitter mode 不可用於該語言 → 自動降 lines mode

**Lines mode（fallback）行為**：
- worker 收到 `backend: lines` 時：
  1. 用 regex / grep 抽方法（語言相依的 simple heuristic）— **不保證準確**
  2. 不嘗試產 callgraph，所有 dependency edges 標 `confidence: unknown`
  3. 輸出帶 `backend: lines` marker
- 後續 sync 無法升 `deterministic-confirmed`，最高只到 `phase5-referenced`

**語言覆蓋**（v1.0 計畫）：
| 語言 | tree-sitter parser | v1.0 支援 |
|---|---|---|
| TypeScript / JavaScript | tree-sitter-typescript / tree-sitter-javascript | ✅ |
| Python | tree-sitter-python | ✅ |
| Go | tree-sitter-go | ✅ |
| Rust | tree-sitter-rust | ✅ |
| C# | tree-sitter-c-sharp | ✅ |
| Bash | tree-sitter-bash | ⚠️ 部分（函式 OK，動態執行不行） |
| 其他 | — | 降 lines mode |

**Backend status 持久化**：sync 每次跑時更新 `.claudedocs/codemap/backend-status.md`：
```markdown
# Codemap Backend Status

<!-- last-sync: <ISO8601> -->
<!-- detected-backend: tree-sitter | lines -->
<!-- tree-sitter-version: <version> | n/a -->

## Per-language coverage

- Python: lines (fallback, tree-sitter-python not installed)
- ...
```

使用者讀此檔可分辨 codemap 整體信任度。

## 設計決策（為後續 Phase 留底）

1. **為何採 3 層索引（per-dir + per-method + dependency map）而非 flat**：對應 progressive disclosure 三個粒度（dir = 大圖、method = 內容、dependency = 影響圖），方法論不同 Phase 用不同層
2. **為何 confidence 必設、不省略**：Type B（hallucination）無法靠 hash 偵測，必須靠 confidence 等級兜底
3. **為何 STALE 不持久化**：避免污染索引；運行時偵測即足
4. **為何 rename 不自動更新**：rename 誤判代價高（IF-x 編號錯位 → 所有依賴關係錯亂）
5. **為何 CLI 不加 `--watch` 自動同步**：違反 Q3 = 「手動進行」決策；自動 watch 增加 forcing function 強度但失去使用者控制
6. **為何 worker 不直接 commit**：保留主 agent 作為單一 source of truth；worker 失敗可重試而不污染 manifest
7. **為何 freshness threshold 改可設定**：避免一刀切（小團隊高頻 vs 大團隊 monthly cadence 差距大）

## 設計決策補充（Round 4/5 新加）

8. **為何接受 tree-sitter 為 optional dep 而非必裝**：保持「prompt skill」核心定位 + 對不裝 tree-sitter 的使用者降級透明（confidence tier `auto-synced` 自然反映低信任）
9. **為何 verifier 改 emit 候選（不直接寫）**：解 codex DR-XR-4 合約矛盾 + 強化「verifier 是 read-only」原則 + 給 sync deterministic check 機會（避免 verifier 誤判直接污染）
10. **為何 `phase5-referenced` 取代 `auto-synced-verified`**：原名稱承諾「verified」但 Phase 5 不驗依賴圖完整性也不驗 LLM 描述準確 — 改窄義避免使用者誤讀
11. **為何 `deterministic-confirmed` 作為最高 tier 而非 `human-validated`**：tree-sitter 機械驗證在「結構性正確」維度比人類眼力更可靠；human-validated 保留給「語義正確」（人類最終 sign-off）
12. **為何 Forward index 為 source of truth，Reverse 機械重生**：並行 worker 對 cross-subtree edges 無全域視野，分頭寫 reverse 必然不對稱（DR-XR-10）；單向 source 統一後問題消失
13. **為何 Round 5 純 spec reconcile 而非真改 live methodology 檔**（DR-R4-1 改寫）：5-Phase 閉環階段紀律 — Phase 1 是設計、Phase 2 是實作；live 檔修訂應與 skill build 在 Phase 2 atomic 改 + 測 + commit，避免「skill 還沒做但 methodology 已先 hook」的 chicken-and-egg 與使用者 prompt 膨脹
14. **為何引入 `quarantined` 狀態**（Round 5 補 DR-R4-4）：verifier 候選經 sync deterministic check 失敗時的明確收容狀態 — 避免狀態機有「pending-review → ??? 」的隱含 black hole；quarantined 讓 agent 明確知道「別信這條 entry」
15. **為何 symbol-id 不是「跨重構穩定」**（Round 5 修 DR-R4-2 + DR-R4-3）：原 Round 4 標 symbol-id 跨重構穩定但實際包含 path，method 移動 = 不同身份；改由 BC-15 rename suspected 流程處理 — 這是「結構正確性 vs 標籤穩定性」的取捨，前者贏（避免誤合併兩個不同的 method）
