# Git 工作流

三個原則：

1. **測試通過就 commit 一次**，不要寫一大堆才 commit。CLAUDE.md 預設「除非用戶另有指示，測試通過後 commit」；你想自己控制節奏就在指令裡說。
2. **有風險的改動前先 commit**，留還原點。重構大段程式、改架構、試不確定的做法，都算。
3. **大功能開分支**，不在主線上改。

## commit message

帶上追溯結果，讓人一眼知道品質狀態：

```
feat: 新增用戶驗證函式

BC-1 ✅ 實作 + 測試 | BC-2 ✅ | BC-3 ✅
審查：0 high · 1 medium（用戶延後）
```

## 分支

| 情境 | 做法 |
|------|------|
| 新功能 | `feature/功能名稱` |
| 修 bug | 小 bug 直接在主線；大 bug 開 `fix/問題描述` |
| 不確定的方案 | `experiment/嘗試內容` |
| 同一任務改了 3 次仍不過 | 停下來問用戶，考慮開新分支重來 |

## 不要做

- 一個 PR 塞十個功能
- commit 追溯表有 ❌ 的程式碼，除非標 WIP
- `git add .`，容易把暫存檔和敏感資料加進去
- force push 到共用分支
