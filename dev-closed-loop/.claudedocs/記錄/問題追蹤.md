# 問題追蹤

## 這份文件是幹嘛的

開發過程中一定會遇到 Bug、踩到坑、發現技術問題。
這些經驗如果不記下來，下次遇到同樣的問題又要重來一遍。

每次遇到問題就在這裡加一筆記錄。不用寫得很正式，但要包含：
- **什麼時候**發生的
- **什麼問題**
- **怎麼解決的**

## 記錄格式

每一筆記錄用這個格式：

```markdown
### [簡短問題標題]

- **時間**：YYYY-MM-DD HH:MM
- **階段**：Phase X（架構師/程序設計師/檢核師/測試師/自証師）
- **嚴重度**：high / medium / low
- **問題描述**：[發生了什麼事，錯誤訊息是什麼]
- **根本原因**：[為什麼會發生這個問題]
- **解決方式**：[怎麼修的，改了哪些地方]
- **學到的教訓**：[下次怎麼避免同樣的問題]
```

## 範例

### 測試框架版本不相容

- **時間**：2026-02-12 14:30
- **階段**：Phase 4（測試師）
- **嚴重度**：medium
- **問題描述**：跑 `npm test` 時出現 `TypeError: expect(...).toHaveBeenCalledOnce is not a function`
- **根本原因**：專案用的是 Jest 28，但 `toHaveBeenCalledOnce` 是 Jest 29 才加的方法
- **解決方式**：改用 `toHaveBeenCalledTimes(1)` 代替
- **學到的教訓**：寫測試前先確認測試框架版本，用 Context7 查 API 支援度

### 自証發現設計規格遺漏邊界條件

- **時間**：2026-02-12 16:00
- **階段**：Phase 5（自証師）
- **嚴重度**：high
- **問題描述**：自証時發現程式碼裡有處理 `null` 輸入的邏輯，但設計規格裡沒有列這個邊界條件。程式碼做了，但設計沒說要做，兩邊對不上。
- **根本原因**：架構師在 Phase 1 漏列了 `null` 作為邊界條件
- **解決方式**：回退到 Phase 1 補上 BC-3（null 輸入），然後 Phase 2-5 重跑
- **學到的教訓**：Phase 1 要更仔細列邊界條件，至少考慮 null、空字串、零、負數、超大值這幾種
